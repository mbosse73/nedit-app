Vier Blöcke lassen sich nicht übersetzen — und es gibt genau vier Wege, damit umzugehen. Diese Entscheidung steht vor der ersten Zeile Code, denn sie bestimmt, wie viele Einträge das Slash-Menü hat und ob die Datei in zehn Jahren noch etwas wert ist. Unten steht, wofür ich mich entscheiden würde und warum.

Was Notion kann und Markdown nicht
Vier Blöcke aus dem Katalog haben in einer .md-Datei keinen Ort: Spalten, Kommentare am Text, synchronisierte Blöcke und Datenbanken. Dazu kommen die Blöcke, die nur über HTML oder einen Dialekt gehen. Für all das gibt es genau vier Antworten — und ein Editor muss sich für eine entscheiden, bevor die erste Zeile Code entsteht.
1

Weglassen

Was nicht in Markdown steht, gibt es nicht. Das Slash-Menü hat fünfzehn Einträge statt vierunddreißig, und die Datei läuft in jedem Werkzeug der Welt.

echtes Markdown
Kein Callout, kein Toggle, keine Spalten, keine Farbe. Dafür: eine Datei, die in zehn Jahren noch geht.
2

HTML einbetten

Markdown erlaubt HTML. <details> wird ein Toggle, <span style> färbt Text. Gültig — aber im nächsten Editor sieht man rohes HTML statt eines Blocks.

HTML
<details> <summary>Entscheidungen</summary> - Keine Abhängigkeiten </details>
3

Einen Dialekt sprechen

GitHub-Alerts für Callouts, ==markiert== für Marker, [[Wiki-Links]] für Erwähnungen. Sieht gut aus — bindet die Datei aber an das Werkzeug, das den Dialekt kennt.

Dialekt
> [!TIP] > Vier davon sind derselbe Export. Das Altsystem läuft seit ==elf Jahren==.
4

Eine zweite Datei führen

.md bleibt sauber, alles Übrige steht daneben in .md.json — Kommentare, Spaltenbreiten, Farben. Zwei Dateien, die zusammengehören und einzeln nichts wert sind.

geht nicht
Ablösung Altsystem.md Ablösung Altsystem.md.json { "kommentare": [ {"zeile": 58, "text": "Rückfrage an Eva"} ] }
Mein Vorschlag

Weg 1 als Vorgabe, Weg 3 als Schalter, Weg 2 nur da, wo Weg 3 nichts anbietet — und Weg 4 gar nicht.

Der Grund steht in der Frage selbst: Wer einen Markdown-Editor will und nicht Notion, will die Datei. Sobald der Inhalt in zwei Dateien liegt, hat man Notions Nachteil (ein Werkzeug versteht es) ohne Notions Vorteil (es kann dafür alles).

Der Dialekt gehört in die Einstellungen, nicht in den Code: Rein · GitHub · Obsidian · Pandoc. Dieselbe Fläche, andere Ausgabe. Und das Slash-Menü blendet aus, was die gewählte Stufe nicht kann — statt es anzubieten und hinterher zu enttäuschen.

Kommentare bleiben draußen. Das ist der schwerste Verzicht, und er ist trotzdem richtig: Ein Kommentar, der beim Kopieren der Datei verschwindet, ist schlimmer als keiner.
